HOW IT WORKS NOW
================================================================================

1. COMPONENT MOUNT:
   → Effect sends: request_reload_status (debounced 300ms)
   → Extension receives request
   → Extension sends back: reload_status_update
   → Server broadcasts to all Expo clients
   → React event listener catches message
   → Sets: lastReloadStatusAt = Date.now()
   → Sets: extensionStatus = "connected"
   → UI shows: "Extension Connected" (green dot)

2. HEALTH CHECK (every 2 seconds):
   → Checks: Date.now() - lastReloadStatusAt
   → If > 15 seconds: extensionStatus = "disconnected" (red dot)
   → If < 15 seconds: extensionStatus = "connected" (green dot)

3. PROFILE CHANGE:
   → selectedSellerProfile changes
   → Effect re-runs (because it's in dependencies)
   → Sends new: request_reload_status request (debounced 300ms)
   → Extension responds with NEW profile's status
   → UI updates to show new profile's reload settings

4. NO UPDATES FOR 15+ SECONDS:
   → Health check timer fires
   → Detects stale data
   → Sets: extensionStatus = "disconnected"
   → User knows extension lost connection

================================================================================
PERFORMANCE IMPROVEMENTS
================================================================================

MESSAGE REDUCTION:
  Before: ~12 request_reload_status messages per minute (5-second polling)
  After:  ~1-3 messages per minute (only on mount/change/save)
  Result: ~85-90% fewer messages to extension

POLLING REMOVAL:
  Before: Continuous 5-second polling interval (wasteful, spammy)
  After:  Event-driven requests only (efficient, clean)

NEW OVERHEAD:
  Health check: 2-second interval running locally (state-only, no network)
  Countdown timer: 1-second interval when timer active (UI update only)
  Both are necessary and minimal

NET RESULT: Lower server load, cleaner logs, better performance

================================================================================
CONNECTION ACCURACY
================================================================================

BEFORE (Wrong):
  extensionStatus = isConnected (tracks Expo↔Server)
  Problem: Shows "connected" even if extension is dead
  Result: False positives, user confusion

AFTER (Correct):
  extensionStatus = tracks lastReloadStatusAt (tracks Extension response)
  Solution: Only marks connected if extension actually sent message
  Result: Accurate status, matches reality

STATUS STATES:
  "checking": Waiting for first response (initial state)
  "connected": Got update in last 15 seconds
  "disconnected": No update for 15+ seconds OR Expo not connected

================================================================================
KEY NUMBERS (TUNABLE)
================================================================================

Debounce timeout: 300ms
  → How long to wait after profile change before sending request
  → Fast enough for responsive UX, slow enough to prevent rapid storms

Health check interval: 2000ms (2 seconds)
  → How often to check if lastReloadStatusAt is stale
  → Good balance between responsiveness and CPU

Connection timeout: 15000ms (15 seconds)
  → How long to wait before marking extension as disconnected
  → Allows for slow extension, network jitter
  → Detects real problems quickly

All three values are adjustable based on requirements.
